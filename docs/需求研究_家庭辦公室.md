# 家庭辦公室：需求研究與落地評估

> 研究範圍：依據提供的〈家庭辦公室 Family Office：需求與開發交接〉，評估第一版的產品界線、資料規則、計算正確性與交付風險。本文不將範例資料視為任何家庭的實際財務資料。

## 結論

這是一份可執行的第一版規格，核心不是「3D 財務展示」，而是讓兩位成員以同一份家庭現況、假設、待討論事項和下一步進行共同決策。最適合的切法是：先完成**可讀、可編輯、可保存的資料與決策工作流**，再將五座島作為相同資料模型的視覺導航層。

單一 HTML + 原生 ES Modules + Three.js 的方向足以完成原型；但 3D 必須是可選的增強體驗。所有重要資訊、表單、待辦與討論都要在 DOM 介面可用，才能符合 WebGL/CDN 失敗、無障礙與手機操作要求。

## 已確認且應直接實作的事實

| 類別 | 確認內容 | 實作含義 |
|---|---|---|
| 家庭組成 | 兩位成人，年齡 42、40；一位 5 歲孩子 | 介面使用中性名稱「成員 A／B」，不可自行配對性別或生日。 |
| 退休時點 | 保留 8 年與 10 年兩種情境 | 這是可切換假設，不是倒數計時器。 |
| 生活目標 | 今天購買力每月 USD 20,000；50 歲後每週工作三天 | 工作收入獨立顯示，預設不納入基本生活支出的必要來源。 |
| 現金流偏好 | 以可用股息支應生活，不出售本金 | 顯示「可用股息」與限制說明；不得把總報酬或本金返還混入。 |
| 範例資產 | 資產 USD 3.2m、負債 USD 0.4m、淨資產 USD 2.8m | 所有數字標籤為「範例」，資料來源為本交接稿。 |
| 第一版界線 | 無真實帳戶串接、登入、雲端同步、稅務結論 | localStorage 僅為本瀏覽器保存，不能寫成多人同步。 |

## 首頁真正要回答的問題

首頁應在不操作 3D 的情況下回答兩件事：

1. **家裡目前狀況如何？** 淨資產、每月可用股息、以今天購買力計的生活費覆蓋率，以及範例／假設標示。
2. **哪些事需要一起處理？** 最多三項優先事項、完整待辦入口、待討論／討論中／已決議狀態、負責人與下次檢視日。

五座島是五個資訊領域的入口；每個島都固定以「現況 → 共同目標 → 差距／注意事項 → 夫妻討論 → 下一步」呈現。這個一致結構會比替每座島發明不同儀表板更容易維護和理解。

## 建議的最小資料模型

所有初始值應集中在單一 `DATA` 物件，並把計算結果維持為衍生值，避免使用者編輯後產生多份互相矛盾的總計。建議分為以下幾類：

```text
DATA
├─ meta: schemaVersion, updatedAt, currency, isExample
├─ household: members, child, planningScenarios
├─ assumptions: monthlyLivingCostToday, inflationRate, usableDividendYield
├─ assets: cash, dividendPortfolio, retirementAccounts, educationFund, home
├─ liabilities: mortgage
├─ contributions: dividendPortfolio, educationFund, retirementAccounts
├─ goals: retirement, education, travel, health
├─ discussions: topic, status, views, decision, nextStep, owner, reviewDate, notes
└─ todos: area, title, priority, owner, reviewDate, completed
```

必要的資料不變量：

- `netWorth = asset total - liability total`，不可由另一個可編輯欄位另存。
- 「可支應生活的股息本金」第一版只取 `dividendPortfolio`；自住房、教育基金、退休帳戶不能加入。
- 教育目標資金只從 `educationFund` 起算；不得同時計入退休可用本金。
- 每年新增投入為外部投入。股息再投入必須是另設的明示假設，不能默默加入。
- `updatedAt` 在本機資料成功修改時更新；匯入 JSON 時也須保存或重新標記更新時間。

## 計算核對

以下以交接稿指定的範例值計算：生活費 `L = 20,000/月`、通膨 `i = 3%`、可用股息率 `y = 3%`、股息本金 `P = 1,800,000`。

| 指標 | 公式 | 精算值 | 建議畫面值 |
|---|---|---:|---:|
| 年可用股息 | `P × y` | USD 54,000 | USD 54,000 |
| 月可用股息 | `P × y ÷ 12` | USD 4,500 | USD 4,500 |
| 今日年生活目標 | `L × 12` | USD 240,000 | USD 240,000 |
| 今日覆蓋率 | `54,000 ÷ 240,000` | 22.5% | 22.5% |
| 今日月缺口 | `L − 4,500` | USD 15,500 | USD 15,500 |
| 8 年後月生活費 | `L × (1 + i)^8` | USD 25,335.40 | 約 USD 25,335 |
| 10 年後月生活費 | `L × (1 + i)^10` | USD 26,878.33 | 約 USD 26,878 |
| 今日所需本金 | `L × 12 ÷ y` | USD 8,000,000 | USD 8.00m |
| 8 年後所需本金 | `L × (1 + i)^8 × 12 ÷ y` | USD 10,134,160.65 | 約 USD 10.13m |
| 10 年後所需本金 | `L × (1 + i)^10 × 12 ÷ y` | USD 10,751,331.03 | 約 USD 10.75m |

交接稿中的 8 年、10 年展示值分別為 `USD 10,134,161`、`USD 10,751,331`，與公式精算結果相符（四捨五入至整數）。實作應以公式即時計算、畫面採合理進位。

輸入防護必須明確：當股息率小於等於 0、不是有限數字，或生活費為負時，所需本金／覆蓋率要顯示「待設定」或驗證錯誤，不能出現 `Infinity`、`NaN` 或錯誤百分比。

## 尚待討論，不能自行補完的決策

1. 兩人各自滿 50 歲減少工作，或採同一年開始。
2. 每月 USD 20,000 是否已包含旅行、住房、醫療、稅金。
3. 台灣與美國的居住時間及兩地住房方案。
4. 美國大學的學校類型、地點及四年費用情境。
5. 股息不足時的優先處理順序。
6. 減少工作前股息再投入與現金使用的比例。
7. 每年 USD 180,000 範例投入如何依真實收支調整。
8. 匯率基準、美元收入／台幣支出處理方式，以及稅務與醫療保障的專業確認。

這些應預建成可更新的討論卡，而非藏在說明文字裡。資料缺失時，系統應使用「待討論」，不可推導「可退休」「保障充足」或任何稅務結論。

## 產品與工程優先序

### P0：必須先成立

- DOM 總覽、財務計算、8／10 年切換與可編輯假設。
- 五個領域的統一詳情面板與文字選單。
- 討論、決議、待辦的新增／更新／勾選完成與 localStorage 保存。
- 範例、假設與資料非同步的清楚標示。
- JSON 匯入欄位驗證、HTML 跳脫／安全 DOM 寫入、匯出、還原範例前確認。
- 無 WebGL／CDN／localStorage 時仍能閱讀資料並獲得可理解提示。

### P1：視覺導航與品質

- 五座可選取的程式生成黏土島、相機聚焦、標籤與鳥瞰。
- 日夜模式、reduced-motion、手機底部詳情面板。
- 以固定 `mulberry32` 種子建立可重現的裝飾物，並依距離隱藏小物。

### P2：可延後的精緻化

- 更豐富的人物、橋梁細節與非關鍵環境動畫。
- 目標資金的情境模擬；前提是先補齊報酬、再投入、投入時點與稅費假設。

## 主要風險與處理方式

| 風險 | 為何重要 | 應採取的處理 |
|---|---|---|
| 3D 先行壓縮核心功能 | 容易交付漂亮但無法共同決策的展示品 | 先以文字與表單完整實作，再把同一資料接入 3D。 |
| 財務概念重複計算 | 退休、教育、自住房若重複分配，缺口會被低估 | 使用單一資產歸屬與衍生總計；在資料驗證中檢查。 |
| 範例被誤當真實資料 | 會導致錯誤信賴與敏感溝通問題 | 卡片、詳情與匯出皆持續標示「範例／待討論」。 |
| localStorage 失敗或資料毀損 | 隱私模式、配額、手動修改都可能發生 | `try/catch`、schema version、安全預設值、匯出備份與不崩潰降級。 |
| CDN 或 WebGL 失效 | 單頁可能只剩空白 | HTML 先渲染資料骨架；3D 初始化獨立包錯；顯示失敗原因與文字入口。 |
| 手機 3D 攔截表單 | 觸控與輸入會不可靠 | 3D 畫布只處理畫布範圍；表單置於具堆疊層級的底部面板，按鈕至少 44px。 |
| 退休推估暗示確定性 | 目前缺少完整報酬／稅費／匯率資料 | 將現況、目標本金、差距分開；情境僅是試算，不輸出退休結論。 |

## 可驗收的測試清單

1. 初始值計算出資產 USD 3.2m、負債 USD 0.4m、淨資產 USD 2.8m；新增投入 USD 180k／年。
2. 初始值顯示月可用股息 USD 4,500、今日覆蓋率 22.5%、月缺口 USD 15,500。
3. 更改通膨、股息率、期限後，未來生活費、所需本金、差距同步更新；0% 與無效輸入不產生非有限值。
4. 退休帳戶、教育基金、自住房不進入生活股息本金；教育基金在教育卡獨立存在。
5. 新增／更新討論與待辦後重新整理，資料仍在；localStorage 故障時介面仍可用。
6. 五座島、文字標籤與清單均可開啟同一主題；鍵盤 Esc 可關閉詳情。
7. 手機寬度下可閱讀摘要、操作表單和按鈕，不靠 hover；reduced motion 停止非必要動畫。
8. 模擬 Three.js 載入或 WebGL 建立失敗時，總覽和資料面板仍可使用且有提示。

## 建議交付定義

第一個可接受版本是一份以本機 HTTP 伺服器開啟的單一 HTML，內含可操作的總覽、五領域資料／討論工作流、持久化與資料備份，再加上可用但節制的五島 3D 視覺。README 應列出啟動命令、實際預覽網址、已實測項目及未做事項；若沒有自動化瀏覽器驗證，必須如實記錄為手動／程式檢查，不能宣稱視覺驗證已完成。
